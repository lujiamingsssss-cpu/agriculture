## §1 选型原则

| # | 原则 |

### 2.1.1 ⚠️ 两个同名陷阱（务必登记，防重复踩）

### ⭐ 选型决定（2026-09-18，T-02 阶段拍板）

**选定 `pyhelios3d` 作为阶段一辐射传输模型。** 理由与代价：

| 项 | 内容 |
|---|---|
| **理由** | ① 官方 wheel 免编译，P4（可安装可复现）最优；② 三维异质冠层 + 逐行几何，直接对应假设 **A2**（条带结构）；③ 本项目演示机（RTX 5060 / driver 596.13）实测跑通 OptiX 8.1 GPU 后端 |
| **代价** | Helios 核心 **GPL-2.0**（见下方风险标注）；**强制要求 GPU**，换到无 GPU 机器即不可用 |
| **备选触发条件** | 出现以下任一情况时切换到 `openalea.ratp`：① 目标运行环境无 GPU；② 本项目需以非 GPL 许可分发。切换到备选时须同时在 `CHANGELOG.md` 记录并重跑判据 C1 |
| **未选备选的原因** | `openalea.ratp` 许可证更宽松（CeCILL-C）且纯 CPU，但**未发布 PyPI**（需源码构建 + 手工配置 MinGW Fortran 运行库），P4 明显劣于首选；其条带表达方式也尚未验证 |

> ⚠️ **A2 仍开放。** T-01 只证明了两者"装得上、核心可调用"，**尚未证明任何一方能正确处理条带结构**。

## §4 Blender 的定位（重要）

| 事项 | 说明 |
|---|---|
| **定位** | 离线渲染器 + 参数化几何生成器（Geometry Nodes + `bpy`） |
| **不承担** | ❌ **不参与辐射传输计算**。Cycles 输出的辐射亮度（radiance）**不等于**光合有效辐射通量（PAR） |
| **数据来源** | 渲染用的颜色/强度必须来自计算层输出（顶点色或纹理） |
| **许可证** | GPL-2.0；通过 `bpy` **调用**不构成链接，不传染自有代码。整包分发需单独评估 |
| **可替换性** | 渲染层必须可替换，不得让计算层依赖它 |

> 学术先例：已有研究用 Blender 做温室补光控制仿真（[*ScienceDirect*](https://www.sciencedirect.com/science/article/pii/S2405896324011492)，NSF 收录）。
> 有先例，但**仍须严格区分"计算"与"表现"**。

## §5 决策记录（Decision Records）

> 本项目的 ADR 内嵌于此，避免为决策记录单开一个目录。

### DR-01 · 用成熟开源辐射模型，不自研

| 项 | 内容 |
|---|---|
| **状态** | ✅ 已采纳 |
| **决策** | 冠层辐射传输必须使用成熟开源模型；禁止自研光线追踪内核 |
| **理由** | 自研内核无法在竞赛周期内达到可验证的物理可信度；且会挤占可视化与交互的工期 |
| **代价** | 受开源模型的接口与许可证约束；可能装不上（假设 A2 风险） |
| **回退** | 若所有候选均不可用 → 阶段一退回简化剖面算法（**必须登记到 `DESIGN.md` 附录 A**），阶段二重估路线 |

### DR-02 · 计算与渲染分离

| 项 | 内容 |
|---|---|
| **状态** | ✅ 已采纳 |
| **决策** | 物理量由数值模型产出；渲染器只负责表现，不引入或修改物理量 |
| **理由** | ① 渲染亮度 ≠ PAR，物理量不对等 ② 渲染帧耗时无法支持参数扫描 ③ 答辩时必须有可复现的计算过程 |
| **代价** | 需要额外维护"计算结果 → 顶点色"的映射代码 |
| **回退** | 无。这是科学诚实的底线 |

### DR-03 · 阶段一简化为二维剖面

| 项 | 内容 |
|---|---|
| **状态** | ✅ 已采纳（阶段一） |
| **决策** | 阶段一计算域为垂直于行向的竖直剖面（假设 H3） |
| **理由** | 平行于行方向统计均匀；计算量降一个数量级；一张剖面图即可让外行看懂 |
| **代价** | 忽略行端效应；地块边角场景不准 |
| **回退** | 阶段二如需三维，扩展计算域（需评估工期） |

### DR-04 · 阶段一允许临时近似（但必须登记）

| 项 | 内容 |
|---|---|
| **状态** | ✅ 已采纳 |
| **决策** | 阶段一允许用简化算法或文献插值快速跑通，条件是**必须登记到 `DESIGN.md` 附录 A** 并写明替换时点 |
| **理由** | 阶段一的目标是验证想法是否成立，不是达到科学严谨；若不设此通道，会在验证前耗光时间 |
| **代价** | 近似结果不能进对外材料；阶段二必须还债 |
| **回退** | 无。但**未登记的近似视为违规** |

### DR-05 · 不做高级优化算法

| 项 | 内容 |
|---|---|
| **状态** | ✅ 已采纳 |
| **决策** | 带型搜索用网格搜索 + 帕累托前沿，不用遗传算法 / 贝叶斯优化 |
| **理由** | 搜索空间约 50 组，网格搜索 5 分钟跑完；简单方法结果可解释、可复现 |
| **代价** | 若未来决策变量连续化，需要换方法 |
| **回退** | 变量空间扩大时重估 |

### DR-06 · 提交信息一律用 `-m` / `-F` 传入，不用 shell 生成文本文件

| 项 | 内容 |
|---|---|
| **状态** | ✅ 已采纳 |
| **决策** | 提交信息写死在 `git commit -m` 参数里，或写入**无 BOM 的 UTF-8 文件**后用 `git commit -F` 读取。禁止先由 PowerShell `Out-File`（或任何默认带 BOM 的写法）生成信息文件再提交 |
| **理由** | PowerShell 5.1 的 `Out-File -Encoding utf8` **会写入 BOM**（U+FEFF）。该字节落入提交对象后，提交标题实际是 `<U+FEFF>docs: …`。**`git log --oneline`（`%s`）会把它当空白吃掉，肉眼完全看不出来**，只有推送后才发现脏——首个提交尤其难补救 |
| **代价** | 多一步校验 |
| **回退** | 推送前用 `git cat-file commit HEAD` 逐字节校验：正文首字符应为 `U+0064`（`d`），且全文不含 `U+FEFF` |
| **备注** | 撤销**已提交**的脏信息：因 root commit 无父提交，`git reset --soft HEAD~1` 会失败，须用 `git update-ref -d HEAD` 撤销后重建。<br>**本规则已被违反过（2026-09-18，T-03 期间）**：用 `Out-File -Encoding utf8` 写提交信息文件，PowerShell 5.1 写入 BOM，导致已推送的提交标题再次带 `U+FEFF`。处置：改用无 BOM 方式生成信息文件，`git reset --soft HEAD~1` 后重建提交，并以 `--force-with-lease` 更新远端。**教训：规则写下来不等于会遵守，提交前逐字节校验这一步不能省。** |

## §6 不选方案的理由（答辩素材）

| 被问到 | 回答要点 |
|---|---|
| 为什么不自研光线追踪？ | 物理可信度无法在周期内验证；成熟模型有同行评议背书（DR-01） |
| 为什么不用深度学习做光分布？ | 光传输有明确物理定律，数据驱动反而丢失可解释性与外推能力 |
| 为什么不用 Cycles 直接算？ | Cycles 输出 radiance 不是 PAR；渲染帧耗时无法支持参数扫描（DR-02） |
| 为什么用 RUE 法而非机理光合模型？ | 本项目做**相对比较**；RUE 参数更易获取、更稳健；机理模型参数无法在周期内标定 |
| 为什么不用遗传算法优化？ | 搜索空间约 50 组，网格搜索更快更可靠（DR-05） |
